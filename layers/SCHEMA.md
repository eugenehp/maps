# Occupancy layers

Who used a building, and when: universities, research labs, startups, and
anything else worth marking. Layers are plain JSON so they can be written by
hand, generated by the pipeline from open data, or exported from the map.

## Source files: `layers/<city>/<layer>.json`

```json
{
  "id": "startups",
  "name": "Startups",
  "description": "Where companies were founded or headquartered.",
  "licence": "CC0 (Wikidata)",
  "publishable": true,
  "generated": false,
  "categories": [
    { "id": "ai",       "name": "AI & ML",          "color": "#7b3fa0", "parent": null },
    { "id": "biotech",  "name": "Biotech & health", "color": "#2e8b57", "parent": null },
    { "id": "services", "name": "IT services",      "color": "#b3aa9c", "parent": null, "off": true }
  ],
  "items": [
    {
      "name": "Example Inc.",
      "category": "ai",
      "tags": ["yc", "founded-here"],
      "role": "founded | hq | office | lab | campus | dorm | other",
      "from": 2015, "to": 2019,
      "where": { "lonlat": [-122.40, 37.78] },
      "wikidata": "Q123",
      "url": "https://…",
      "note": "One or two sentences.",
      "source": "wikidata | overture-places | osm | ipeds | user | …"
    }
  ]
}
```

- `where` is exactly one of:
  - `{ "lonlat": [lon, lat] }`: the building containing the point, else the nearest within 25 m.
  - `{ "address": "185 3rd St" }`: matched against the city's address index.
  - `{ "gid": 123 }`: a building id. Only valid for the build it came from, so the pipeline also writes lonlat on export.
  - `{ "polygon": [[lon, lat], …] }`: every building whose centroid is inside. Use this for campuses.
- `from` and `to` are years. Either may be null, which means unknown or still there.
- `category` refers to `categories[].id`. Categories may nest one level through `parent`, e.g. `ai` under `software`.
- `off: true` on a category: shown in the legend but switched off until the user turns it on (K-12 schools, IT agencies).
- `tags` are free-form labels. The UI can filter on them, e.g. `yc`, `unicorn`, `acquired`, `mit-spinout`.
- `generated: true` marks files written by `pipeline <city> layers`; those are regenerated on every run. Any
  other file (no flag, or `false`) is never touched and is ingested as is — this is where hand-written and
  browser-exported layers go. To edit a generated layer by hand, set `generated` to false first.
- The generated layers are `academia`, `startups`, `companies` and `neurotech` (see "Generated layers" below).
- `publishable: false` on a layer: for local use only. `pipeline site` leaves such layers out of the published
  `layers.json` / `layers.bin` (the city itself is still published) unless `--include-local` is given.

## Pipeline output: `web/data/<city>/layers.json` + `layers.bin`

- **`layers.json`:** `{ layers: [{id, name, description, licence, publishable, categories: [{id, name, color, parent, bit}]}], itemColumns: […], items: [[layerIdx, catIdx, name, role, from, to, url, note, wikidata, sourceIdx, tags]], sources: […] }`.
  - Every category gets a global bit, 0–63 (the build fails beyond 64).
  - `catIdx` indexes the item's layer's `categories`; `sourceIdx` indexes `sources`; `tags` is an array (added
    as the 11th column; `itemColumns` names them all).
  - The item index is the position in `items`. Items whose `where` doesn't resolve are not in `items`.
- **`layers.bin`:** little-endian, magic `'SFL2'`, u32 nB, u32 nLinks.
  - Next, `mask u32[2*nB]`: two words per building (low word first), giving that building's 64 category bits.
    An item sets its category's bit **and its parent's bit**, so filtering on `software` also finds `ai`.
  - Next, `linkStart u32[nB+1]`, then `link u32[nLinks]`: the CSR list of item indices for each building, so the card can list every occupant with its years.

(Not to be confused with `land.bin` etc., whose magic is `'SFL1'` — a different file type.)

## Resolution details

- `lonlat`: building containing the point (outer ring minus holes), else the building whose outline is nearest
  within 25 m.
- `address`: normalised (lower case, punctuation dropped, Street→st, Avenue→ave, …) and matched exactly against
  the city's attrs addresses; every building with that address matches.
- `polygon`: every building whose footprint centroid is inside.
- `gid`: passed through if in range.

## Generated layers

- `academia` — categories `university`, `college`, `research`, `hospital` (teaching hospital / medical school),
  `school` (K-12; give it a muted colour / off by default), `dorm`. Sources: Overture land_use education
  polygons (OSM campus outlines, `polygon` items), Wikidata (P31/P279* university Q3918, college Q189004,
  research institute Q31855, medical school Q494230, university hospital Q1059324, national lab Q1144475,
  school Q3914; P571/P576 → from/to), Overture places (college_university, research institutes, medical
  schools, university housing, K-12 schools). Duplicates merge on the same Q-id, a point inside a
  similarly named campus, or within 100 m with a similar name.
- `startups` — Wikidata enterprises (P31/P279* Q4830453) founded ≥ 1970 that are not nonprofits / government
  bodies and map to a tech/bio category (or are a "startup company" Q131524), plus current tech offices from
  Overture places (role `office`, from/to null). Categories: `software` (`ai`, `devtools`, `saas`, `consumer`,
  `gaming`, `security`, `fintech`, `crypto`), `hardware` (`semiconductors`, `devices`, `robotics`, `space`,
  `energy`, `transport`), `bio` (`biotech`, `pharma`, `medtech`, `healthtech`), `other`, and `services`
  (IT services, app-development shops and agencies; off by default). Tags: `acquired` (P127/P749), `public`
  (P414), `defunct` (P576), `startup` (Q131524). No `unicorn` tag: no reliable open signal.
- `companies` — the remaining Wikidata enterprises (older, non-tech, or no inception), by sector: `tech`,
  `finance`, `professional`, `media` (with arts and venues), `retail`, `food` (with bars and hotels),
  `realestate`, `industry`, `transport`, `health`, `nonprofit`, `other`. Libraries, schools, agencies and
  buildings that Wikidata also files under "business" are left out.

- `neurotech` — neuroscience, neurotech and BCI companies from the neurotech index (`../neurotech/neurotech.db`,
  or `$NEUROTECH_DB`; read with `sqlite3 -readonly` into `cache/neurotech.json` on every run, which is the fallback
  when the database is missing). US companies only, and only facts: name, website, founding year (`from`), status
  (tags `public`, `acquired`, `defunct`, `subsidiary`, `academic`, `nonprofit`). Category = the primary segment:
  `bci`, `neuromodulation`, `imaging`, `monitoring` (diagnostics, neuromonitoring), `pharma` (with psychedelics,
  neurogenetics, neuro-oncology), `digital` (digital therapeutics, neuro-AI), `consumer` (with sleep tech),
  `devices` (neurosurgery, prosthetics, sensory restoration, rehab), `tools` (research tools, organoids, contract
  manufacturing, clinical trials), `advocacy` (off by default), `other`. Located by, in order: an HQ or office
  street address in the city that is in the address index (mailboxes and mail-drops skipped); the office among
  the Overture places by website host (the company's site and its other domains; same rules as below); the exact
  name among office-like places, only when the index puts the HQ or an office in the city. Role `hq` when the
  index's HQ city is in the city, else `office`. The index states no licence, so the layer is
  `publishable: false`.

### Where a company is

In order, the first that gives a point:

1. its own coordinate (P625);
2. its headquarters (P159): the HQ item's coordinate, or a coordinate qualifier (P625) on the statement, with
   from/to from P580/P582;
3. when the headquarters is just the city: its office among the Overture places, found by the place's
   brand Wikidata id, else the website host (bare site URLs only; social-media and site-builder hosts and
   hosts with more than 3 places never match), else the exact name (only places with an office-like
   category, at most 3 of them). The office beats a bare street address (P6375), which is often a
   registered agent's;
4. the street address (P6375) or an address qualifier, matched against the city's addresses.

Coordinates with ≤ 3 decimals on both ordinates, or equal (to 4 decimals) to a settlement / neighbourhood
item's coordinate, are dropped: they are city centroids, not buildings.

### Categories

- **Wikidata companies:** industry (P452) labels, then type (P31) labels, then keywords in the name and
  website (`.ai` hosts, "Robotics", "Therapeutics"…), then the category of the office found. The name also
  beats a generic industry ("Scale AI": software industry → `ai`).
- **Overture offices:** keywords in the name and website, else the place category (`software_development` →
  `saas`, `web_designer` → `services`, …). See `crates/pipeline/src/classify.rs`.

### Mail-drops

Overture lists hundreds of "companies" at mail-drop addresses (548 Market St, 2261 Market St in SF): virtual
offices and registered agents, not occupants. A street address with at least 5 private mailboxes (`PMB`),
making up at least 15% of the places there, is a mail-drop. Tech listings there, and any listing with a PMB,
are dropped, and no company is placed there.

## Browser marks

Marks made in the map use the item format above, with `source: "user"` and `where.lonlat` set to the building's point on its surface. They are kept in IndexedDB per city. The map exports them as a layer file that you can drop into `layers/<city>/` and rebuild.

- `datacenters` — publishable. Categories `datacenter`, `cloud` (company-owned, by operator), `hall` (a data hall
  of ≥ 10,000 ft² in a larger building), `exchange` (telephone exchanges and central offices), `planned`.
  Sources, merged into one item per facility (an outline containing the point, else ≤ 35 m, else ≤ 80 m with a
  similar name or the same operator):
  - PNNL IM3 Open Source Data Center Atlas (ODbL): building and campus outlines, operator, floor area;
  - OpenStreetMap (`telecom=data_center`, `building=data_center`, `telecom=exchange`; Overpass API, ODbL);
  - Compute Atlas (CC BY 4.0): status, MW, plans; exact-precision records only;
  - lists compiled from operators' own location pages and from California government records (Energy Commission
    backup-generation dockets, CEQAnet, San José / Santa Clara / Hayward planning):
    `cache/datacenters/<source>/open.json`, placed by coordinates, the city's address index, else Overture
    address points (number + street + ZIP), only records in the city's state;
  - energy disclosures: NYC LL84 (data-centre floor area, IT load, PUE; Verizon central offices as `exchange`),
    Boston BERDO, Cambridge BEUDO; SF Assessor parcels of class "Industrial Data Center".
- `datacenters-local` — local use only, left out of the static site: PeeringDB interconnection facilities
  (`carrier`: an exchange point or ≥ 20 networks present; `colo`; `cloud`), each with its operator and how many
  networks and exchange points it hosts (PeeringDB's terms forbid redistribution without permission), plus any
  facility list in `cache/datacenters/<source>/facilities.json`:
  `{ "source", "licence", "publishable", "facilities": [{ "name", "lat", "lon", "operator?", "status?", "opened?", "mw?", "url?" }] }`
  (`planned` for planned / under-construction status).
